## 2. 入っている主な機能（2026-10-26 時点、main は PR #16 まで反映済み・未マージの PR なし）
- Gmail からのオファー自動取り込み（メルマガは除外）：`tools/gmail-import.gs`（Google Apps Script）＋ 設定 → データ。手順書 `docs/gmail-import.md`

- 逆質問タブの「これからの予定:」ボタン：カレンダーの予定がある企業を近い順に自動で並べる（PR #15）

## 3. 守ること（ユーザーとの約束）
- **説明は日本語で、初学者にも分かるように。** 専門用語には一言説明を添える。
- 合言葉（KEY）やパスワードを Claude が入力欄に打ち込まない。Google へのログインと「許可」ボタンはユーザーが押す。Apps Script の `KEY` の行は触らず、前後だけを置き換える。
- 公開・共有に関わるボタン（Apps Script のデプロイ、PR のマージなど）は、押す前に確認する。
- 変更の流れ：作業ブランチ → コミット → プッシュ → PR（gh は `"C:\Program Files\GitHub CLI\gh.exe"` をフルパスで）→ ユーザーが「マージして」と言ったらマージ → 公開サイトの反映を確認。main に直接入れない。
- 見た目は `docs/design-guidelines.md` に従う（色は `--ds-*` 変数、絵文字なし）。
- 動作確認：`.claude/launch.json` を作って簡易サーバー（node）を起動し preview_start。確認後は `launch.json` を消して**コミットしない**。パスワード画面はローカルだけ `unlockDashboard(false)` で通せる。Google の応答は `window.fetch` を差し替えてまねる。
- `index.html` の作業コピーは CRLF（改行コード）。node で置換するときは改行をそろえてから編集し、最後に CRLF に戻す。複数行の置換や正規表現は、スクリプトファイルにして実行する。
- 「同じ予定」の基準を変えるとき（例：時間が同じなら種類が違っても同じ、とする）は、必ずユーザーに確認する。
- 「見えない」と言われたら、コードを触る前に `docs/lessons-learned.md` のチェックリストに従う（画面が古くないか、設定 → データの状態が「未設定」でないか、同期が遅れているだけではないか）。
