# 同じミスを繰り返さないためのメモ（原因と直し方）

カレンダーまわりで「1つ直すと別のところがおかしくなる」ことが続いたため、これまでの原因と直し方をまとめました。
**作業を始める前に、必ずこのファイルを読むこと**（AIに頼むときも読ませてください）。

---

## 0. 作業前チェックリスト

1. **まず、見えない原因が「コード」か「その端末のデータ・設定」かを分ける**
   - データは端末（ブラウザ）ごとに別。公開サイトのコードが最新でも、端末に予定が入っていなければ何も出ない。
   - 確認する順番：①画面が古くないか（再読み込み）→ ②設定 → データの状態の文言（「未設定」か）→ ③カレンダータブにその予定が入っているか → ④それでもおかしいときだけコードを見る。
2. **「何が同じ予定か」「何を対象にするか」の基準を変えるときは、必ずユーザーに確認する**（勝手に変えない）。
3. **「次の予定」「次の面接」など、日付が入る表示は、必ずカレンダーのデータから作る**。文字や会社名を直接書かない。
4. **直したあとは、その画面だけでなく、同じデータを使う他の画面（ホーム・カレンダー・企業カード・一覧・表・逆質問）も確認する**。
5. **実際のデータで試す**：Google カレンダーの本物の予定を、同期の処理に通して、追加・更新・対象外が何件になるかを見てから「直った」と言う。
6. 動作確認用のファイル（`.claude/launch.json` など）はコミットしない。

---

## 1. 原因と直し方の一覧

### ① 端末に予定が入っていない（同期の設定が無い）
- **症状**：ホームに「次の面接」が出ない。予定が古い日付のまま。
- **原因**：「Apps Script の URL」と「合言葉」は端末ごとに保存される。普段使いのブラウザには、一度も入れていなかった（入れていたのはアプリ内ブラウザだけ）。コードの不具合ではなかった。
- **直し方**：設定 → データに、Apps Script の URL と合言葉を入れて「保存して今すぐ取り込む」。
- **次から**：「見えない」と言われたら、先に設定 → データの「状態：」が「未設定」でないかを聞く。コードを触る前に。

### ② 表示が「いちばん近い1件」しか見せていなかった
- **症状**：同じ日に予定が複数あっても1つしか出ない。面接が「他○件」に隠れる。
- **原因**：ホームが「今日と明日」の予定の先頭だけを見せていた。カレンダーの日付の枠が、件数が多いと省略していた。
- **直し方**：ホームは「これからの予定（2週間）」を日付ごとに全件表示。面接は先頭に出して印を付けた。
- **次から**：表示を作るときは「同じ日に複数あるとき」「面接が混ざるとき」を必ずテストする。

### ③ 企業の画面の「次の予定」が、手書きのメモのままだった
- **症状**：企業のカードに「面接日程予約中」のままの古い文字が出て、決まった面接日が出ない。
- **原因**：企業ごとの「次の予定」の欄は手で書くメモ。カレンダーとは連動していなかった。
- **直し方**：カレンダーのいちばん近い面接を別の行で出し、メモはその下に残した。
- **次から**：手で書く欄と、カレンダーから作る欄を、画面の上で分けて見せる。

### ④ 同じ予定が重なる／「同じ予定」の基準がぶれた
- **症状**：同じ予定が2つ出る。直したら、別の予定が消えた。
- **原因**：「同じ予定」の基準が、直すたびに変わっていた（日付と種類だけ → 日付・開始と終了の時間・種類）。Google に同じ予定が2つあることもある。
- **直し方**：基準を「同じ会社・同じ日・同じ開始と終了の時間・同じ種類」に決め、一致するものだけ1件にまとめる。違うものは両方残す。ホームにお知らせして、「元に戻す」を付けた。
- **次から**：基準を変えたいときはユーザーに確認する（時間が同じなら種類が違っても同じ、など）。

### ⑤ オファーの返信期限の予定が古くなる／締切と重なる
- **症状**：オファーの期限を変えても、カレンダーの予定が古いまま。ES締切と同じ日で二重に出る。
- **原因**：オファーの期限から作った予定（`cal-offer-` で始まる）が、オファーの編集と連動していなかった。
- **直し方**：期限や種類を変えたら、対応する予定も一緒に更新。同じ日にES締切があれば、作らない。
- **次から**：同じ情報を2か所に持つ場合は、片方を直したらもう片方も直す処理を必ず入れる。

### ⑥ ボタンや文字を、コードに直接書いていた
- **症状**：逆質問の「クイック選択」が固定の8社で、NCD が「本日10:00」のまま古くなった。
- **原因**：会社名と日付の文字をコードに直接書いていた。
- **直し方**：カレンダーの予定がある企業を、近い順に自動で作るようにした。
- **次から**：日付・会社名・件数など、時間とともに変わる値は、コードに書かない。

### ⑦ 「変更なし」と出て、理由が分からない
- **症状**：同期して「変更はありませんでした」と出るが、本当に最新なのか分からない。
- **原因**：同期は、**登録済みの会社名がタイトルか説明に入っていて、種類を読み取れた予定だけ**を対象にする。それ以外は黙って対象外にする。直前の取り込みで、すでに更新が済んでいることもある。
- **対応**：「変更なし」のときは、①直前に自動で同期されていないか、②Google の予定のタイトルに会社名が入っているか、を先に確認する。
- **改善の候補**：対象外にした予定の件数と理由を、同期の結果に出す。

## 2. 最近の「はまりやすい」運用上の注意
- `index.html` の作業コピーは CRLF（改行コード）。node で置換するときは、改行をそろえてから編集し、最後に CRLF に戻す。
- Apps Script は `KEY` の行を触らない。貼り替えるときは前後だけ置き換える。デプロイは「新バージョン」にすると URL は変わらない。
- 公開・共有に関わる操作（デプロイ、PRのマージ）は、ユーザーの確認を取ってから行う。
- アプリ内ブラウザのデータは、ユーザーの実際のデータとは別物。
- Google 側のスクリプトを変えたら、①保存、②（権限が増えるなら）確認用の関数を実行して許可、③「新バージョン」でデプロイ、の3つが必要。
